# 가상 상황과 성능 목표

## 1. 문서 목적

성능 개선의 배경이 되는 가상 상황과 성능 검증 기준을 정의한다.

예약 공개 직후 조회 요청이 집중되는 상황을 가정하고, 주어진 실행 환경과 데이터 규모에서 예약 및 대기 목록 조회 API가 안정적으로 처리해야 할 트래픽과 성능 목표를 설정한다.

## 2. 가상 상황

예약 공개 직후 사용자가 자신의 예약 상태와 대기 순번을 반복해서 확인하면서, 예약 및 대기 목록 조회 요청이 일시적으로 증가한다고 가정한다.

트래픽이 집중되는 시간대에는 다음과 같은 현상이 관찰된다.

* 예약 및 대기 목록 화면의 로딩 시간이 평상시보다 길어진다.
* 요청이 증가할수록 일부 요청의 응답 지연이 두드러진다.
* 사용자로부터 목록 조회가 느리다는 문의가 발생한다.

현재 관찰된 현상만으로는 요청 처리 과정 중 어느 지점에서 지연이 발생하는지 알 수 없다.

따라서 성능 테스트를 통해 조회 지연을 재현하고, 트래픽 증가에 따른 성능 변화를 확인한다. 이후 요청 처리 과정을 분석하여 실제 병목 지점을 찾고, 적절한 개선 방법을 적용한다.

## 3. 실행 환경

| 구분     | 환경                         |
|--------|----------------------------|
| 서버     | AWS EC2                    |
| 인스턴스   | t4g.micro                  |
| CPU    | 2 vCPU                     |
| 메모리    | 1 GiB                      |
| 애플리케이션 | Spring Boot                |
| 데이터베이스 | MySQL                      |
| 서버 구성  | 단일 EC2에서 애플리케이션과 데이터베이스 실행 |

## 4. 데이터 조건

| 데이터                     |      규모 |
|-------------------------|--------:|
| 전체 예약 수                 | 10,000건 |
| 전체 예약 대기 수              | 30,000건 |
| 대기가 존재하는 슬롯의 평균 대기 수    |     30건 |
| 예약을 보유한 사용자의 평균 예약 수    |      3건 |
| 예약 대기를 보유한 사용자의 평균 대기 수 |      5건 |

예약과 예약 대기는 서비스가 일정 기간 운영되면서 누적된 데이터라고 가정한다.

대기가 존재하는 슬롯은 평균적으로 30건의 예약 대기를 가진다. 예약을 보유한 사용자는 평균 3건의 예약을 가지며, 예약 대기를 보유한 사용자는 평균 5건의 예약 대기를 가진다.

## 5. 트래픽 규모

| 항목              |      값 |
| --------------- | -----: |
| 목표 트래픽          | 18 RPS |
| 스트레스 테스트 최대 요청량 | 25 RPS |

`목표 트래픽`은 서비스가 성능 목표를 만족하면서 안정적으로 처리해야 하는 요청량을 의미한다.

`스트레스 테스트 최대 요청량`은 목표 트래픽을 넘어 요청량을 단계적으로 증가시키면서, 응답 시간 급증이나 처리량 정체, 오류 증가가 나타나는 구간을 확인하기 위한 상한이다.

## 6. 성능 목표

| 지표        |          목표 |
| --------- | ----------: |
| 평균 응답 시간  |    500ms 이하 |
| p95 응답 시간 |  1,000ms 이하 |
| 오류율       |       1% 이하 |
| 평균 성공 처리량 | 17.1 RPS 이상 |

성능 목표는 목표 트래픽인 18 RPS가 유지되는 동안 만족해야 하는 기준으로 정의한다.

평균 응답 시간은 전체적인 조회 성능을 확인하기 위한 지표이며, p95 응답 시간은 일부 느린 요청을 포함하더라도 전체 요청의 95%가 1초 이내에 처리되는지 확인하기 위한 지표다.

평균 성공 처리량은 부하 발생 및 측정 과정의 오차를 고려하여 목표 트래픽의 95%인 17.1 RPS 이상으로 설정한다.

## 7. 대상 API

```http
GET /reservations
```

## 8. 현재 처리 흐름

```text
요청 수신
→ 사용자의 예약 목록 조회
→ 사용자의 예약 대기 목록 조회
→ 예약 대기별 현재 순번 계산
→ 응답 생성
```

현재 처리 흐름은 분석 대상을 파악하기 위해 기록한다. 각 처리 구간이 전체 성능에 미치는 영향은 이후 테스트 결과를 바탕으로 판단한다.
